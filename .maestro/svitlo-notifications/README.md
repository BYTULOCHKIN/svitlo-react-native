# Native-пілот історії

Підготовлені два окремі flows. Вони використовують ізольоване E2E-сховище та локальний API із [серверного пілота](../../server/notifications/README.md).

1. Зібрати Android development APK із SecureStore та Expo Notifications; запустити локальний сервер і Metro з `EXPO_PUBLIC_E2E=1`, `EXPO_PUBLIC_NOTIFICATIONS_API_URL=http://127.0.0.1:8787`.
2. Виконати `adb reverse tcp:8787 tcp:8787` та reverse для порту Metro.
3. Запустити `01-empty-history.yaml` із відповідними `APP_ID`, `DEV_URL` і `RESET_URL`: він обирає чергу, відкладає пояснення дозволу кнопкою «Пізніше», підключає інсталяцію й перевіряє порожню історію. Якщо пояснення з’явилося пізніше через повільний сервер, відкласти його й повторити перехід до вкладки; цей історичний flow не є перевіркою native permission.
4. Виконати `pnpm notifications:fixture` на комп’ютері. Fixture вставляється після реєстрації інсталяції.
5. Запустити `02-publication-history.yaml`: перевірити картку публікації й дату графіка.
6. Повторити команду fixture та другий flow для перевірки відсутності дублікатів і збереження після нового запуску.

Для нового повного сценарію використовувати новий локальний файл через `SVITLO_LOCAL_DB` в обох серверних командах. Нова інсталяція не отримує раніше опубліковану fixture навіть після повторної команди — це очікувана поведінка початку історії.

Стан на 11 жовтня 2026 року: після перепідключення Samsung SM-S928U1 / Android 16 APK встановлено, `01-empty-history.yaml` пройшов із реальною HTTPS адресою Worker та ізольованим E2E-сховищем. Початкове очікування перевіряє фактичний екран, а не назву застосунку на splash. Через асинхронну появу пояснення його опційне закриття може потребувати повтору flow. `02-publication-history.yaml` на цьому кроці не запускався; реальна картка публікації перевірена окремо через ADB.

Maestro може автоматично надавати дозволи при запуску драйвера. `01-empty-history.yaml` задає `notifications: unset` і після цього скидає тільки E2E-інсталяцію. Цей flow не доводить системний grant/deny або реальний push. Такі сценарії перевірено окремо на Samsung і описано в звіті задачі 02; iOS і screen reader не перевірено.

Для реального push, дозволу й перевірки Cloudflare використовується окремий [сценарій задачі 02](../../server/notifications/pilot.md).
