# Android-віджет Svitlo

Локальний Expo-модуль; автопідключається з `modules/` при генерації Android-проєкту. Публічний контракт JS: синхронізувати збережені локації та прочитати датований кеш. Віджет рендериться й оновлюється нативно, без постійно запущеного JS.

## Поведінка

- Одна прив'язка `appWidgetId → locationId` на екземпляр, незалежна від активного вибору застосунку. Системна конфігурація та кнопка налаштування у самому віджеті відкривають вибір локації.
- Локації й API-конфігурація передаються із застосунку у приватні SharedPreferences. Bridge відключений в ізольованому E2E-режимі, щоб тестовий набір локацій не підмінив звичайні віджети.
- Кеш за датами зберігає вчора/сьогодні/завтра. Кожна відповідь перевіряється до запису; старіший `verifiedAt` не замінює новіший. 404 — недоступний графік, не підтвердження відсутності відключень.
- Одна WorkManager periodic-задача на всі екземпляри, цільовий інтервал 15 хвилин, із вимогою мережі. Ручне оновлення має окреме unique work та обмежені повтори; запити не виконуються паралельно. Невдала перевірка зберігає кеш і час джерела.
- Локальний приблизний хвилинний перерахунок використовує inexact RTC alarm, який не будить телефон. Система може затримати його. Постійного foreground service, exact-alarm дозволу та вимоги дозволу push немає.
- Після reboot/package replace відновлюються рендер і планування; зміна системного часу перераховує дані. Після видалення останнього екземпляра скасовуються work і alarm. Android Force stop залишається системним обмеженням.
- Статус, відлік, восьмигодинне вікно й добові рядки обчислюються окремо від Android UI та HTTP. Київський часовий пояс має сумісний alias для старих Android; DST розраховується за реальними часовими межами.
- Таймлайн — bitmap із текстовим описом. Решта вмісту та дії — стандартні RemoteViews. Перед вибором рядків вимірюється шрифт Inter з урахуванням ширини; переповнення відкриває повний графік відповідної локації/дати.

## Перевірки 9 листопада 2026

- Expo autolinking знаходить `ua.svitlo.widget.SvitloWidgetModule`.
- Нативні debug/release компілюються; 21 JUnit/Robolectric-тест PASS: контракт графіка (4), стійке сховище й прив'язки (3), API → кеш/помилки (3), розрахунки часу/дат/DST/overflow (7), реальний RemoteViews і мінімальний розмір із native preview (2), WorkManager (1), вимірювання рядків (1).
- 112 тестів Svitlo PASS, включно з 9 новими: JS/native sync змін локацій, переходи з віджета, завтрашня дата та кеш за помилки API.
- Серверні регресії: 58/58 PASS. Перший sandbox-запуск не дозволяв локальний bind тестового проксі; повтор із дозволом на локальний HTTP завершився успішно.
- TypeScript і design generation check PASS. Повний lint перевіряється без згенерованих Gradle-звітів; зміна ignores стосується лише build/.gradle локальних Android-модулів.
- Фізичне приймання Samsung і APK — окремий етап [09](../../plans/svitlo-android-widget/09-samsung-widget-acceptance.issue.md). Фінальний APK готується після виправлення DST; пристроєві сценарії ще не позначені PASS. Попередні APK build 4–5 скасовані в черзі й не встановлювалися.
- Production CNG, JS-бандл і merged manifest PASS; у production-пакеті перевірені provider/configuration/system receiver та WorkManager initializer. Для локального бандла використано Node 22 і новий Gradle daemon; старий daemon підхоплював несумісний Node.
- Native preview `.tmp/widget-native-preview.png`: контрольований графік з імітованою недоступністю API; перевірені 300×400 dp та мінімальні 250×320 dp зі звичайним шрифтом.
- Великий системний шрифт і TalkBack виключені з перевірок за уточненням користувача. Віджет не змінює ці системні налаштування для приймання.

З кореня після Expo Android prebuild: `cd android`, потім `./gradlew :svitlo-widget:testDebugUnitTest :svitlo-widget:assembleRelease`. Потрібні сумісний JDK (використано Android Studio JBR), Android SDK та дозволений доступ до залежностей. Тестові дані ізольовані, реальних push вони не надсилають.
