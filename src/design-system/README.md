# Дизайн-система Svitlo

Єдине джерело значень — `tokens.ts`: семантичні кольори й поверхні, чотири стани світла, відступи, радіуси, Inter, типографічні ролі, розміри й інтеракції. `features/svitlo/theme.ts` містить лише продуктові назви станів та посилання на ці токени. `components/ui/colors.ts` — сумісний експорт палітр із того ж джерела.

Поточний дизайн темний незалежно від системної теми: екрани, navigation theme, системний status bar та кореневий фон узгоджені. Світлий варіант потребує окремого дизайну. Токени використовуються також у native Expo config; Kotlin launcher artwork збережено.

`AppText` задає базову типографіку. `AppPressable` забезпечує мінімальний touch target і стан натискання. `ActionButton` має основний і другорядний варіанти. Для заголовків, пояснень і цифр використовувати `typography`, для компонентних розмірів — `metrics`. Flex, абсолютне позиціювання та дані графіка є правилами структури, а не новими дизайн-токенами.

## Компоненти пілота локацій

`@gluestack-ui/core` 5.0.15 та `@gluestack-ui/utils` 5.0.6 зафіксовані в lockfile. Використовуємо creator API без зміни Expo 54, React Native 0.81 або UniWind 1.2.4; оформлення задається наявними токенами через StyleSheet. Продуктові споживачі імпортують тільки наші обгортки:

- `AppText`: `variant` із typography та семантичний `tone`; масштабується системним шрифтом.
- `AppButton`: primary, secondary, ghost, danger; disabled та loading блокують дію, loading зберігає назву й повідомляє busy. `AppIconButton` вимагає доступну назву. `ActionButton` збережений як сумісна обгортка.
- `AppInput`: обов’язкова видима назва, helper/error, доступний опис, native ref, disabled. Адаптер залишає вимкнене поле видимим для читача екрана та задає native editable відповідно до readOnly gluestack.
- `AppDialog`: контрольований open, заголовок, єдиний onRequestClose для кнопки, фону, accessibility escape і native Back; safe area, keyboard avoidance та прокручування всього вмісту. Факт закриття визначає споживач.
- `AppConfirmDialog`: безпечне скасування при будь-якому запиті закриття. `AppConfirmDialogBody` дозволяє формі змінити вміст існуючого діалогу без другої native modal window; чернетка залишається у батьківській формі. Фокус запитується на безпечну дію; після скасування — на поле назви.
- `AppChoiceGrid`: контрольована radio group; видима позначка й checked, опціонально вимкнені пункти, колонки за фактичною шириною та fontScale. Довгі назви можуть переноситися; немає ліміту в три символи чи неявного вибору черги.

Точність поведінки TalkBack/VoiceOver, keyboard avoidance та переходів фокусу приймається на пристроях у [задачі 06](../../plans/svitlo-component-foundation/06-native-location-pilot-acceptance.issue.md). Успішний JS export не є native або screen reader прийманням. Старі template компоненти залишаються окремими; їх сумісність перевіряється регресійними тестами та задачею 11.

`npm run design:contrast` перевіряє 31 комбінацію кольорів пілота, включно з alpha поверхонь і станом натискання: текст — щонайменше 4.5:1, позначки вибору й рамки контролів — 3:1. Перевірка порівнює неокруглені значення; вимкнені контроли виключені. `motion.pressedOpacity` дорівнює 0.86, щоб натискання не знижувало контраст тексту кнопок нижче вимоги; `motion.disabledOpacity` окремо зберігає значення 0.72. `check-all` включає `design:check` та `design:contrast`. Це перевірка токенів, а native відображення та фокус потребують перевірки на пристроях.

## Іконки

Усі іконки інтерфейсу використовують `lucide-react-native` через `AppIcon` із `icon.tsx`. Кольори, розміри й товщина лінії беруться з токенів; кожна з 29 іконок має прямий імпорт з `lucide-react-native/icons/<canonical-name>`. Повний каталог бібліотеки не імпортується. Нові іконки додавати до явної таблиці відповідностей. `Zap` і `ZapOff` позначають наступну подію в картці статусу.

`SvitloIcon` та старі експорти `components/ui/icons` залишені як сумісні посилання/обгортки, але більше не містять власних SVG-контурів. Назви збережених іконок локацій не змінені: `home → House`, `work → BriefcaseBusiness`, `school → GraduationCap`, `shop → ShoppingCart`, `gym → Dumbbell`, `parents → Users`, `cafe → Coffee`, `heart → Heart`. Для посилання GitHub використано нейтральний символ коду `CodeXml`. Стрілка в спільному UI зберігає RTL-віддзеркалення.

Позначки вибору, чекбокси й закриття діалогів теж використовують Lucide. Градієнти та великі SVG-ілюстрації не є іконками й залишаються графічними елементами. Оригінальна launcher-іконка з Kotlin збережена; лампа splash відповідає Lucide `Lightbulb` 1.55.0, ліцензія — `assets/lucide-LICENSE.txt`. Android APK із цим splash зібрана, але під час встановлення ADB не бачив пристрою. Metro запущено на порту 8081.

Jest обробляє `.mjs` бібліотеки через Babel; іконки в наявних компонентних тестах не замінюються заглушками.

Перевірка переходу: TypeScript та ESLint проходять, 13 suites / 70 тестів успішні, JavaScript bundles Android та iOS експортовані. Native Android assembleDebug успішний; встановлення і візуальна перевірка нової лампи на пристрої очікують підключення телефона. Нативний запуск iOS не перевірявся.

`src/global.css` генерується з токенів, а не редагується вручну:

```sh
npm run design:generate
npm run design:check
```

Генерація покриває кольори, шрифт, базовий крок відступів, радіуси й текстові розміри Tailwind/Uniwind. Після зміни native branding потрібна перебудова; JS-стилі оновлюються через Metro. Демонстраційні екрани шаблону залишаються поза продуктовою навігацією; їх повна переробка не входить до цього редизайну.

## Головна

Порядок: назва й київська дата → локація → статус і відлік → попередження про актуальність даних → графік. Картка відтворює оформлення Kotlin `HeroStatusCard.kt`: насичений градієнт, центровані лампа й кольоровий заголовок, темний блок відліку з моноширинними цифрами та двокрапками. Розміри елементів і відступи зменшено до компактної картки: близько 207 dp із таймером і 118 dp без нього при стандартному шрифті. Кольори картки — `statusCardColors`, інші стани інтерфейсу — `powerColors`.

Час отримання графіка (`snapshot.updatedAt`) показано праворуч угорі як «Оновлено HH:mm» за Києвом; повна дата доступна для озвучення. Час не змінюється через локальний відлік чи невдале оновлення. Попередження про збережений графік, помилки збереження та оновлення залишаються під карткою. При великому системному шрифті відлік переходить у вертикальне компонування, час займає окремий рядок праворуч; висота вмісту може зростати для доступності. Для дня без відключень немає вигаданого таймера, пояснення явно повідомляє, що відключення не заплановані.

Таймлайн відтворює Kotlin `ScheduleTimeline.kt`: кольорова поверхня кожного інтервалу, іконка в комірці 48 dp, радіус 16 dp, мінімальна висота 70 dp; поточна картка має мінімум 110 dp, рамку, позначку «ЗАРАЗ» і час до наступної відомої події. `timelineColors` містить зелені й червоні кольори Kotlin та додаткові жовтий стан можливого відключення й нейтральний стан невідомих даних. Висота може зростати для великого шрифту; час і позначка переносяться. Для невідомої наступної події відлік не вигадується.

Назва локації та черга розміщені в окремих рядках, довгі назви переносяться. Діалог вибору локації центрований у safe area, закриття через фон не перехоплює натискання на вміст.

API, збереження локацій, правила станів, кеш і годинник залишаються в наявних модулях. Перевірки: TypeScript, ESLint, 13 suites / 70 тестів, синхронність CSS з токенами; JavaScript export для Android та iOS, Android native build та встановлення успішні. У bundle включено лише чотири потрібні накреслення Inter. Фінальна візуальна перевірка на пристрої, збільшеного шрифту та нативного iOS ще не підтверджена. Спроба знімка була пропущена, оскільки наш застосунок уже не був видимим.
