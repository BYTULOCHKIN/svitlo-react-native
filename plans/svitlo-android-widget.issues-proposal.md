# Пропозиція задач: Android-віджет Svitlo

Дата: 9 листопада 2026 року.

Джерело: [PRD](./svitlo-android-widget.prd.md).

Статус: розбиття на дев'ять задач, залежності та AFK/HITL погоджено користувачем. Перевірки великого системного шрифту й TalkBack виключено за його уточненням; перевірка зміни розміру залишається. Окремі [issue-файли та індекс](./svitlo-android-widget/README.md) створено. Код 01–08 реалізовано, автоматичні перевірки PASS; фізичне приймання 09 триває.

Кожна задача — наскрізний результат, який можна показати або перевірити самостійно. Сховище, нативний код, інтеграція із застосунком, UI й релевантні тести вводяться разом із першою поведінкою, яка їх потребує. Базові empty/error states, правильна дата, доступні назви та ізоляція тестових даних не відкладаються до останніх задач.

AFK — реалізація за вже погодженими вимогами без нового продуктового рішення. HITL — фактичне приймання з участю користувача; код і перевірюваний сценарій готуються до нього.

## 01. Додати віджет обраної локації й відкрити її в застосунку

Тип: AFK. Blocked by: немає. User stories: 1–5, 7–8, 12–13, 31, 39, 41, 45.

Запланований файл: `01-add-location-widget.issue.md`.

### What to build

Користувач додає системний Android-віджет, обирає збережену локацію й бачить її назву, чергу та поточний плановий стан із датованого API. Натискання відкриває цю локацію на головному екрані застосунку. Це мінімальна вертикаль на реальному нативному віджеті, а не лише React Native preview.

### Acceptance criteria

- [ ] Віджет реєструється в лаунчері; нативна інтеграція відтворюється при генерації та компіляції Android, включно з production-конфігурацією.
- [ ] Вибір зі збережених локацій, відсутність локацій із переходом до створення та скасування конфігурації мають завершені сценарії без довільного вибору адреси.
- [ ] Два екземпляри зберігають незалежні widget ID → location ID; зміна активної локації застосунку не змінює їх. Локація не вибирається за індексом чи назвою.
- [ ] Валідна відповідь API правильної дати показує `on`/`off`/`possible`; невідомі дані дають явний стан відсутності, а не «світло є». Статус явно за графіком, є час перевірки.
- [ ] Основне натискання відкриває правильну збережену локацію при холодному й теплому запуску; віджет не потребує дозволу push. Кольори/типографіка беруться з узгодженого стилю Svitlo.
- [ ] Є unit/інтеграційне покриття контракту й конфігурації, доступні назви та перевірювана Android-збірка; fixture-дані ізольовані від production.

## 02. Переналаштувати віджет і синхронізувати зміни локації

Тип: AFK. Blocked by: 01. User stories: 6–11.

Запланований файл: `02-widget-location-lifecycle.issue.md`.

### What to build

Користувач змінює прив'язку вже доданого віджета. Редагування локації у застосунку оновлює пов'язані віджети; видалення показує empty/error state з вибором іншої локації.

### Acceptance criteria

- [ ] Повторна конфігурація змінює лише обраний екземпляр; скасування залишає стару прив'язку. Передбачено доступний шлях там, де лаунчер не показує системне «Налаштувати».
- [ ] Перейменування й зміна черги проходять через стійкий обмін даними до всіх прив'язаних віджетів без ручного повторного додавання.
- [ ] Після видалення показується «Локацію видалено — оберіть іншу»; вибір іншої відновлює роботу. Інша локація автоматично не підставляється.
- [ ] Повторний запуск процесу зберігає прив'язки та стан; запізніла відповідь для старої черги або видаленої локації не перезаписує нову прив'язку.
- [ ] Інтеграційні сценарії охоплюють два екземпляри, одну адресу в кількох віджетах, редагування/видалення й скасування, без зміни користувацьких production-даних тестом.

## 03. Оновити графік вручну та читати кеш офлайн

Тип: AFK. Blocked by: 01. User stories: 33–39.

Запланований файл: `03-manual-refresh-offline-cache.issue.md`.

### What to build

Кнопка «Оновити» отримує графік через Render і зберігає валідний датований кеш. Після втрати мережі віджет зберігає корисні дані й показує їхній вік та помилку без підміни дат.

### Acceptance criteria

- [ ] Повний шлях ручне натискання → стан виконання → API → валідація → кеш → віджет завершується даними або зрозумілою помилкою. Повторні натискання не створюють необмежених паралельних запитів.
- [ ] Кеш за датами переживає смерть процесу; неправильна дата/структура відповіді не руйнує останній валідний графік. Графік попередньої дати не подається як сьогоднішній.
- [ ] Час перевірки походить із успішної перевірки джерела; timeout/5xx/невалідна відповідь його не оновлюють. Після 30 хвилин є «Дані можуть бути застарілими» та кваліфікація розрахунку за кешем.
- [ ] Розрізняються немає кешу, помилка з кешем, немає графіка на дату та валідна відсутність відключень. 404 не перетворюється на вигадане твердження про стан джерела.
- [ ] Контрольовані інтеграційні тести охоплюють офлайн/restart, граничний вік 30 хвилин, повторне натискання та застарілу відповідь API.

## 04. Отримувати фонові оновлення без відкритого застосунку

Тип: AFK. Blocked by: 02, 03. User stories: 32, 34, 40–41, 46.

Запланований файл: `04-background-widget-refresh.issue.md`.

### What to build

Закритий застосунок не перешкоджає запланованим фоновим перевіркам графіка. Після перезапуску телефона відновлюються конфігурація й кеш; після видалення останнього віджета зайва робота припиняється.

### Acceptance criteria

- [ ] Планується приблизно 15-хвилинна мережева перевірка через відповідний Android-планувальник, без постійного JS/foreground service і без вимоги дозволу push.
- [ ] Успішний фоновий API-цикл оновлює видимий віджет та час перевірки. Є обмежені повтори, координація з ручним оновленням і спільне використання графіків між екземплярами.
- [ ] Нативний цикл може читати прив'язки й кеш без відкриття React Native екрана. Смерть процесу та reboot не втрачають налаштувань; відновлення виконується після доступності користувацького сховища.
- [ ] Видалення одного екземпляра не зупиняє інші; після видалення останнього періодична робота скасовується.
- [ ] Вимірювання відрізняє час постановки задачі від фактичного виконання. Doze/енергозбереження та системний Force stop задокументовані без обіцянки точної періодичності.
- [ ] Інтеграційний/native сценарій доводить оновлення рендера зі звичайно закритим застосунком, збереження стану й коректне прибирання робіт.

## 05. Показувати відлік і переходи графіка через північ

Тип: AFK. Blocked by: 03, 04. User stories: 12–17, 37–38.

Запланований файл: `05-status-countdown-and-midnight.issue.md`.

### What to build

Віджет показує приблизний час до наступної відомої зміни планового стану та правильно переходить між інтервалами й датами за Europe/Kyiv. Розрахунок виконується з кешу окремо від мережевої перевірки.

### Acceptance criteria

- [ ] Для відомих переходів є правильний статус, підпис і відлік у годинах/хвилинах без секунд. Перехід у `possible` не названо гарантованим відновленням.
- [ ] Локальний перерахунок не потребує мережевого запиту щохвилини; на наступному рендері після межі статус/відлік відповідають поточному часу, а не завершеній події.
- [ ] Потрібні датовані графіки завантажуються/кешуються; безперервний `off` через північ не дає хибного відновлення о 00:00. Якщо наступного графіка чи події немає, це показано явно.
- [ ] Вік даних лишається чесним при локальному перерахунку; застарілий кеш позначений, минула дата не використовується як сьогоднішня.
- [ ] Детерміновані тести охоплюють київський час незалежно від зони телефона, DST, сусідні однакові інтервали, межі дат, невідомі ділянки й зміну системного часу. Є перевірка розрахунку на видимому нативному віджеті.

## 06. Читати найближчі вісім годин на таймлайні

Тип: AFK. Blocked by: 05. User stories: 18–21, 44.

Запланований файл: `06-eight-hour-widget-timeline.issue.md`.

### What to build

Валідовані датовані графіки перетворюються на читабельний таймлайн від −2 до +6 годин із поточним моментом, часовими підписами й доступним текстовим описом.

### Acceptance criteria

- [ ] Таймлайн показує погоджене вікно й маркер «зараз», коректні відносні довжини інтервалів і підписи за Europe/Kyiv.
- [ ] `off`, `possible` та відсутні дані відрізняються; статус не передається лише кольором.
- [ ] Вікно продовжується через північ; необхідна минула дата береться з датованого кешу/API, недоступні ділянки залишаються невідомими.
- [ ] DST і обрізання інтервалів краями вікна не вигадують подій або тривалості; модель перевіряється незалежно від рендера.
- [ ] Видимий Android-віджет відтворює таймлайн з API/кешу; інформація часових інтервалів і поточного моменту також має текстовий опис.

## 07. Читати сьогодні/завтра й відкривати повний графік

Тип: AFK. Blocked by: 05. User stories: 22–30, 38.

Запланований файл: `07-today-tomorrow-outage-lists.issue.md`.

### What to build

У двох колонках віджета користувач читає інтервали на сьогодні й завтра. Якщо місця недостатньо, бачить актуальні пріоритетні рядки та відкриває решту за правильною датою через «Ще N».

### Acceptance criteria

- [ ] Обидві дати проходять API → датований кеш → списки з початком, завершенням і тривалістю; можливі відключення позначені явно.
- [ ] За достатнього місця показано всі рядки, минулі приглушені, поточний виділений. За браку місця завершені не витісняють поточні/найближчі; «Ще N» точно рахує приховані рядки.
- [ ] Немає графіка/помилка доступу й валідне «Відключень не заплановано» мають різні тексти відповідно до реальної інформації API.
- [ ] Натискання «Ще N» відкриває повний графік відповідної локації та дати, включно із завтра, при холодному й теплому запуску. Дату не підміняє головний екран; за недоступності потрібної дати є явний стан.
- [ ] Тести охоплюють багато інтервалів, `possible`, день без відключень, відсутнє завтра, безперервне відключення через північ, точний overflow і маршрутизацію.

## 08. Користуватися повним віджетом при зміні розміру

Тип: AFK. Blocked by: 02, 04, 06, 07. User stories: 8, 28–29, 42–45.

Запланований файл: `08-adaptive-widget.issue.md`.

### What to build

Повний наскрізний віджет адаптується до доступної площі: локація, статус, таймлайн, списки та дії залишаються придатними для використання. Базові доступні назви й текстові описи зберігаються; окремі перевірки великого шрифту й TalkBack не виконуються.

### Acceptance criteria

- [ ] Початковий великий формат орієнтовно 4×4, підтримується resize; мінімальний розмір обрано за читабельністю, без додавання компактного режиму.
- [ ] Композиція референсу відтворена нашими кольорами/типографікою. Довга назва, черга, статус і час перевірки не перекривають одне одного.
- [ ] При звичайному системному шрифті та мінімальному розмірі інформація не втрачається через необґрунтоване обрізання: менше рядків і доступний «Ще N», читабельний таймлайн і статус.
- [ ] Інтеграційні/native-перевірки використовують реальні дані контрольованого API, різні розміри, довгі назви й багато інтервалів. Type-check, lint, релевантні тести та Android-компіляція проходять.

## 09. Прийняти production-віджет на Samsung

Тип: HITL. Blocked by: 08. User stories: 1–46.

Запланований файл: `09-samsung-widget-acceptance.issue.md`.

### What to build

Підписана production-подібна Android-збірка проходить фактичне приймання повного користувацького сценарію на Samsung. Готується відтворюваний звіт; за успішного приймання — production APK з віджетом.

Участь користувача: доступний розблокований телефон і потрібні підтвердження Android. Агент готує збірку, сценарії та докази до цих кроків; відсутність пристрою не є підставою позначити тест пройденим. Зміна системного шрифту та ввімкнення TalkBack для приймання не потрібні.

### Acceptance criteria

- [ ] Встановлення з поточним production-підписом зберігає локації/сповіщення; системне додавання, скасування, повторна конфігурація, два незалежні екземпляри й видалення перевірені в лаунчері Samsung.
- [ ] На реальному віджеті звірені статус/відлік, таймлайн, сьогодні/завтра, недоступні дані, ручне оновлення, переходи в потрібні локацію/дату, редагування та видалення локації.
- [ ] Фактичне фонове виконання виміряне зі звичайно закритим застосунком; reboot, офлайн/recovery, енергозбереження та відмова push перевірені. Затримки Android задокументовані; Force stop не маскується під звичайне закриття.
- [ ] Resize і мінімальний розмір зі звичайним системним шрифтом перевірені фізично, включно з натисканням дій. Налаштування телефона й користувацькі дані після тестів відновлені.
- [ ] Відтворювана збірка, type-check, lint, релевантні тести й регресії поточного застосунку PASS; звіт відрізняє автоматичні, контрольовані та реальні фонові докази.
- [ ] Production APK перевірено за пакетом, версією й підписом, доступний користувачу. Неперевірені лаунчери/версії Android не оголошуються перевіреними.

## Погодження розбиття

Користувач погодив розмір задач, залежності та AFK/HITL з поправкою: виключити перевірки великого шрифту й TalkBack. Створено дев'ять окремих `.issue.md` та індекс із посиланнями на блокери. Це локальні планові документи; GitHub issues не публікувалися, поточні статуси реалізації наведено в індексі задач.
