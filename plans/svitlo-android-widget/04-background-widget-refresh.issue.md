# 04. Отримувати фонові оновлення без відкритого застосунку

Тип: AFK.

Статус: реалізовано; автоматичні перевірки PASS, фізичне приймання — у задачі 09.

Джерело: [PRD](../svitlo-android-widget.prd.md). [Погоджене розбиття](../svitlo-android-widget.issues-proposal.md).

User stories PRD: 32, 34, 40–41, 46.

## What to build

Закритий застосунок не перешкоджає запланованим фоновим перевіркам графіка. Після перезапуску телефона відновлюються конфігурація й кеш; після видалення останнього віджета зайва робота припиняється.

## Acceptance criteria

- [ ] Планується приблизно 15-хвилинна мережева перевірка через відповідний Android-планувальник, без постійного JS/foreground service і без вимоги дозволу push.
- [ ] Успішний фоновий API-цикл оновлює видимий віджет та час перевірки. Є обмежені повтори, координація з ручним оновленням і спільне використання графіків між екземплярами.
- [ ] Нативний цикл може читати прив'язки й кеш без відкриття React Native екрана. Смерть процесу та reboot не втрачають налаштувань; відновлення виконується після доступності користувацького сховища.
- [ ] Видалення одного екземпляра не зупиняє інші; після видалення останнього періодична робота скасовується.
- [ ] Вимірювання відрізняє час постановки задачі від фактичного виконання. Doze/енергозбереження та системний Force stop задокументовані без обіцянки точної періодичності.
- [ ] Інтеграційний/native сценарій доводить оновлення рендера зі звичайно закритим застосунком, збереження стану й коректне прибирання робіт.

## Межі перевірок

За уточненням користувача перевірки великого системного шрифту та TalkBack не входять до цієї роботи й не є блокерами приймання. Перевірка зміни розміру віджета залишається у відповідних задачах. Базові доступні назви й текстові позначення станів зберігаються.
