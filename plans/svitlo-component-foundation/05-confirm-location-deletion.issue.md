# 05. Підтвердження видалення локації

Тип: AFK.

Статус: реалізовано; Android E2E PASS, iOS-приймання — задача 06.

Джерело: [PRD](../svitlo-component-foundation.prd.md).

User stories PRD: 33, 34, 35, 36, 37, 38, 40, 47, 48, 49, 57, 58.

## What to build

Запросити видалення у формі, перевірити назву локації та підтвердити або скасувати через AppConfirmDialog. Після успіху показати правильну наступну локацію або повернутися до першого вибору черги.

## Acceptance criteria

- [x] Підтвердження показує правильну назву, безпечну дію «Скасувати» та небезпечну «Видалити».
- [x] Скасування повертає форму зі збереженою чернеткою; закриття підтвердження означає безпечне скасування.
- [x] Успіх закриває форму; немає другого підтвердження відкидання тієї самої чернетки.
- [x] Видалення неактивної, активної та останньої локації зберігає поточні правила сховища.
- [x] Помилка запису зберігає локацію та показує доступну помилку без удаваного успіху.
- [x] Інтеграційні й E2E-тести перевіряють скасування, успіх, останню локацію та відновлення даних; TypeScript, lint і регресійні тести проходять.

Підтвердження використовує збережену назву локації, безпечне скасування й explicit destructive action. Інтеграційні тести покривають збереження чернетки при скасуванні, видалення активної/неактивної/останньої локації, відновлення store та storage failure/retry. 10.10.2026 native E2E cancel, delete, restart і повернення до onboarding після останньої локації пройшов на Samsung SM-S928U1, Android 16, fontScale 1.0. Після скасування підтвердження тест прокручує форму до дії видалення при відкритій клавіатурі. TypeScript, lint і регресійний набір пройшли. iOS-приймання залишається у задачі 06.
