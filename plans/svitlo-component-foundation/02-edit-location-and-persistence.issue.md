# 02. Редагування локації та відновлення даних

Тип: AFK.

Статус: реалізовано; Android E2E PASS, iOS-приймання — задача 06.

Джерело: [PRD](../svitlo-component-foundation.prd.md).

User stories PRD: 20, 21, 22, 26, 27, 28, 54, 57, 58.

## What to build

Перенести редагування на ту саму форму й спільні компоненти: завантажити наявну назву, іконку та чергу, записати зміни без випадкового перемикання активної локації та перевірити відновлення після перезапуску.

## Acceptance criteria

- [x] Діалог редагування має правильний заголовок та початкові значення вибраної локації.
- [x] Оновлюється лише потрібна локація; активна локація зберігається за поточними правилами.
- [x] Збережена черга присутня у виборі навіть за відсутності в поточному переліку оператора.
- [x] Помилка редагування не змінює підтверджені дані, не закриває форму й не губить чернетку.
- [x] Інтеграційні тести та розширений E2E перевіряють редагування, trim і відновлення записаних значень після перезапуску.
- [x] TypeScript, lint і релевантні тести проходять.

Єдина LocationDialog завантажує початкові значення, зберігає відсутню в операторському списку чергу та не перемикає активну локацію. Інтеграційні тести перевіряють edit активної/неактивної локації, trim, відновлення нового store із записаних даних і storage failure/retry. 10.10.2026 розширений E2E edit/restart пройшов на Samsung SM-S928U1, Android 16, fontScale 1.0: назва Apartment після trim, черга 2.1 та активна Office відновилися після restart. Native дерево також підтвердило checked для іконки Кохані. TypeScript, lint і регресійний набір пройшли. iOS та ручні скринрідери залишаються у задачі 06.
