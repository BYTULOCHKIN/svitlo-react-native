# 09. Актуальність після опівночі та повернення в застосунок

Статус: виконано; реалізація та автоматизовані перевірки завершені. Платформне приймання — issue 10.
Джерело: [PRD](../svitlo-react-native-migration.prd.md).

Тип: HITL. User stories: 13, 16–18, 23–24, 27–28.

Погодження: користувач підтвердив Europe/Kyiv незалежно від часового поясу пристрою та перевірку дати після опівночі й повернення у foreground. Щосекундно змінюється тільки локальний час; мережевий запит виконується для нового дня або застарілих даних при поверненні.

Окремо погоджено один компонентний тест локального годинника для сценарію background → active; це не погодження довільного додаткового E2E-покриття.

## What to build

Користувач залишає застосунок відкритим до наступного дня або повертається після перерви. Екрани перевіряють актуальну дату, переобчислюють стан і таймер та отримують новий графік за потреби. Дані вчорашнього дня не видаються за сьогоднішні.

Погодити запропоновані в PRD технічні уточнення: часовий пояс `Europe/Kyiv` незалежно від налаштування пристрою та перевірку дати при опівночі й поверненні у foreground. Це не фонова періодична робота й не механізм сповіщень.

## Acceptance criteria

- [x] Часовий пояс і поведінка опівночі/foreground погоджені та задокументовані.
- [x] Формат дати запиту та розрахунки стану використовують спільне правило часу, включно з пристроєм в іншому часовому поясі.
- [x] Після зміни дати попередній графік відразу втрачає право визначати поточний стан і таймер.
- [x] Новий графік завантажується без потреби перемикати локацію або перезапускати застосунок.
- [x] Після повернення у foreground відлік відновлюється за поточним часом, а не за кількістю пропущених tick-подій.
- [x] За невдалого запиту нового дня збережені попередні дані залишаються явно позначеними.
- [x] Unit-тести охоплюють опівніч, зміну часового поясу пристрою та відсутність даних нового дня; сценарій повернення перевірений на платформі або компонентним тестом у погодженому обсязі.
- [x] TypeScript і ESLint проходять.

## Validation

TypeScript, ESLint та 70/70 тестів пройдено. Unit-тести перевіряють київську опівніч, незалежність від локальних методів Date, зимовий час, зміну UTC-зсуву й втрату актуальності графіка попереднього дня. Погоджений компонентний тест перевіряє зупинку tick-подій у background, негайне відновлення за реальним часом наступного дня та очищення таймера і підписки після unmount. Hermes export для Android та iOS успішний; це не підтверджує нативний запуск.
