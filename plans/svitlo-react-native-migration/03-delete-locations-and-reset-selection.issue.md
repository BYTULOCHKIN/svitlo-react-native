# 03. Видалення локацій і повернення до вибору черги

Статус: заплановано; поділ погоджений користувачем.
Джерело: [PRD](../svitlo-react-native-migration.prd.md).

Тип: AFK. User stories: 10–12, 25, 28.

## What to build

Користувач видаляє локацію через наявний сценарій редагування. Видалення активної локації переводить його на одну з решти, а видалення останньої повертає до явної пропозиції вибрати чергу. Дані не відновлюються помилково після перезапуску.

## Acceptance criteria

- [ ] Видалення неактивної локації не змінює поточний графік.
- [ ] Після видалення активної локації за наявності інших вибирається перша з решти, відповідно до Kotlin-поведінки.
- [ ] Останню локацію можна видалити; активний вибір очищується, персональні статус і таймер зникають.
- [ ] Порожній стан містить явний заклик обрати чергу; повторний вибір знову створює «Дім».
- [ ] Видалення збережене між запусками й не скасовується пізнім результатом запиту.
- [ ] Unit-тести покривають видалення неактивної, активної та останньої локації; TypeScript і ESLint проходять.
