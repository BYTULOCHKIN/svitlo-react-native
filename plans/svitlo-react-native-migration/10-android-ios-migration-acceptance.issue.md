# 10. Приймання перенесеної версії на Android та iOS

Статус: підготовлено до нативного приймання; завершення заблоковане відсутністю платформного середовища. Задача не виконана.
Джерело: [PRD](../svitlo-react-native-migration.prd.md).

Тип: HITL. User stories: 1–28, в межах першого етапу PRD.

## What to build

Завершити перенесення перевіркою всіх погоджених сценаріїв на Android та iOS, усунути виявлені платформні проблеми й підготувати короткий звіт про виконання критеріїв PRD. Порівняння вигляду виконується за Kotlin-кодом; редизайн не проводиться.

Це наскрізне приймання застосунку, а не відкладене написання тестів для всіх попередніх задач. Кожна попередня задача вже має власну перевірку. Людська участь потрібна для перегляду результату та забезпечення платформного середовища, якщо його немає.

## Acceptance criteria

- [ ] Є перевірені запуск і основні сценарії на Android та iOS; відсутнє середовище позначається як блокер, а не як успішна перевірка.
- [ ] Android-версія встановлюється поряд із Kotlin-версією без заміни її даних.
- [ ] Пройдені перший вибір, CRUD локацій, видалення останньої, статуси, таймер, таблиця, ручне оновлення та повторний запуск без інтернету.
- [ ] Діалоги, клавіатура, safe area, системна кнопка назад Android та прокручування таблиці не блокують користування.
- [x] Вкладка сповіщень порожня; відсутні шаблонні продуктові екрани, віджети й фонові сповіщення.
- [ ] Перевірено вигляд за реально використовуваним Kotlin-кодом; не заявляється піксельна відповідність без перевірки оригіналу.
- [x] Поточний API-контракт перевірений; обмеження щодо зразка явної відповіді без відключень, якщо залишилися, зазначені у звіті та не приховані.
- [x] TypeScript, ESLint та погоджені тести проходять; додаткові інтеграційні, компонентні та автоматизовані E2E не вважаються погодженими без рішення щодо тестового обсягу.
- [ ] Видимі зміни поведінки й виправлення переглянуті власником продукту; підготовлено результат для початку окремого редизайну.
- [x] Збірки не прив’язані до шаблонного EAS-проєкту Obytes; якщо потрібен EAS, реальна прив’язка погоджена. Публікація в магазинах не виконується.

## Звіт перед платформним прийманням

Issues 01–09 реалізовані та збережені окремими комітами. TypeScript та ESLint проходять; Jest: 13 suites, 70/70 тестів. Один компонентний тест background → active погоджено окремо і виконано. У демонстраційних тестах Obytes залишаються попередження React act та відкритих ресурсів; продуктовий тест годинника проходить із перевіркою очищення таймера й підписки.

Expo export після issue 09 успішно створює Hermes bundles Android та iOS приблизно по 6.67 MB. Артефакти локальні, ігноруються Git: `.tmp/issue-09-export`. Це перевірка пакування JavaScript, а не нативна збірка, встановлення чи запуск.

Реальна відповідь Полтаваобленерго перевірена для таблиці 12 підчерг і для датованого обласного повідомлення без запланованих відключень: [контракт](./poe-contract.md). Обидва формати мають збережені тестові фікстури. Інші формулювання явного повідомлення автоматично не підтверджуються.

Продуктова навігація містить лише головну, черги та порожні сповіщення. Компонування перенесене з реально використовуваних Kotlin-компонентів: темна палітра, картка стану, таймер, шкала, локації та матриця. Піксельна відповідність без запуску оригіналу не заявляється. Package/bundle identifiers `ua.svitlo.rn` із суфіксами середовищ відрізняються від Kotlin `com.yourname.svitlode`; фактичне одночасне встановлення ще не перевірене. EAS owner/project задаються тільки реальними змінними середовища, шаблонна прив’язка прибрана.

Блокер середовища: Windows; `adb`, `java`, `emulator` відсутні у PATH, стандартний каталог Android SDK відсутній. iOS-приймання потребує Mac/Xcode або погодженої нативної збірки та пристрою. EAS-проєкт не створювався, віддалені збірки та публікація не запускались. Власнику продукту надіслано запит про доступне середовище.

Виявлено залишки шаблону: `assets/icon.png` містить логотип Obytes; стартовий splash та adaptive icon також потребують перевірки перед встановленням. Перенесення оригінальної іконки запропоновано власнику продукту, погодження очікується. Скрипт `e2e-test` і `.maestro` залишилися демонстраційними та не є перевіркою Svitlo; автоматизований E2E не заявляється виконаним.

## Сценарії для Android та iOS

Після забезпечення SDK/JDK для Android або Xcode для iOS встановити development build через `pnpm android` / `pnpm ios`. Застосунок використовує MMKV/Nitro та потребує нативної development build; Expo Go не є платформним прийманням цього репозиторію.

| Сценарій | Очікуваний результат | Android | iOS |
|---|---|---|---|
| Чисте встановлення | Жодної вибраної черги; явна пропозиція обрати | Не перевірено | Не перевірено |
| Перший вибір | Створено Дім з вибраною чергою; відображено реальні дані | Не перевірено | Не перевірено |
| CRUD та перемикання локацій | Назва, іконка, черга й активний вибір зберігаються | Не перевірено | Не перевірено |
| Видалення останньої локації | Повернення до явного вибору черги | Не перевірено | Не перевірено |
| Стани й таймер | Чотири стани; можливе відключення не назване гарантованим; відлік без від’ємних значень | Не перевірено | Не перевірено |
| Повний день світла / обласне повідомлення | Текст без запланованих відключень; без вигаданого таймера | Не перевірено | Не перевірено |
| Матриця черг | Активна черга виділена; таблиця прокручується | Не перевірено | Не перевірено |
| Pull-to-refresh, помилка та повтор | Індикатор завершується; попередні дані збережені; успіх прибирає помилку | Не перевірено | Не перевірено |
| Перезапуск без мережі | Збережений графік із датою/часом; учорашній не визначає сьогоднішній статус | Не перевірено | Не перевірено |
| Опівніч та background → active | Київська дата; новий день отримує новий графік; час відновлюється одразу | Не перевірено | Не перевірено |
| Діалоги, клавіатура, safe area, назад | Ввід і закриття працюють; елементи доступні | Не перевірено | Не перевірено |
| Встановлення поряд з Kotlin | Окремі додатки та дані | Не перевірено | Не застосовується |
| Сповіщення | Порожня вкладка; фонових повідомлень немає | Не перевірено | Не перевірено |

Після проходження сценаріїв потрібен перегляд результату власником продукту. До цього issue 10 та перший етап міграції не закриваються.
