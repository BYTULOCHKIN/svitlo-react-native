# 07. Ручне оновлення та відновлення після помилки

Статус: виконано; реалізація та автоматизовані перевірки завершені. Платформне приймання — issue 10.
Джерело: [PRD](../svitlo-react-native-migration.prd.md).

Тип: AFK. User stories: 19–20, 28.

## What to build

Користувач оновлює графік жестом потягування й бачить результат запиту. Після невдалого запиту він може повторити спробу, а успішний результат прибирає помилку та синхронізує всі екрани, що використовують цей графік.

## Acceptance criteria

- [x] Pull-to-refresh головного екрана виконує новий запит для поточної дати, навіть якщо графік уже є в пам’яті.
- [x] Індикатор завершується після успіху та після помилки; повторні дії не створюють неконтрольованих паралельних запитів.
- [x] Останні коректні дані не знищуються перед отриманням заміни; помилка оновлення відрізняється від початкової відсутності даних.
- [x] Після успішного повтору попередня помилка очищується й видимі дані оновлюються.
- [x] Якщо загальна таблиця вже реалізована, вона бачить той самий оновлений графік без другого джерела стану.
- [x] Unit-тести перевіряють результати успіху та помилки; інтеграційний тест повторного запиту є запропонованим додатковим покриттям PRD.
- [x] TypeScript і ESLint проходять.

## Validation

Ручне оновлення використовує спільний query cache, не очищує коректні дані й не скасовує активний запит повторними жестами. API має 15-секундний timeout та очищення ресурсів. Успіх, HTTP-помилка, мережева помилка й некоректний HTML перевірені; 62/62 тестів пройдено.

TypeScript та ESLint пройдено. Jest пройдено; наявні попередження демонстраційної форми Obytes не належать продуктовому сценарію Svitlo. Нативне приймання не заявляється виконаним.
