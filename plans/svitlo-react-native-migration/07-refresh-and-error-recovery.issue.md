# 07. Ручне оновлення та відновлення після помилки

Статус: заплановано; поділ погоджений користувачем.
Джерело: [PRD](../svitlo-react-native-migration.prd.md).

Тип: AFK. User stories: 19–20, 28.

## What to build

Користувач оновлює графік жестом потягування й бачить результат запиту. Після невдалого запиту він може повторити спробу, а успішний результат прибирає помилку та синхронізує всі екрани, що використовують цей графік.

## Acceptance criteria

- [ ] Pull-to-refresh головного екрана виконує новий запит для поточної дати, навіть якщо графік уже є в пам’яті.
- [ ] Індикатор завершується після успіху та після помилки; повторні дії не створюють неконтрольованих паралельних запитів.
- [ ] Останні коректні дані не знищуються перед отриманням заміни; помилка оновлення відрізняється від початкової відсутності даних.
- [ ] Після успішного повтору попередня помилка очищується й видимі дані оновлюються.
- [ ] Якщо загальна таблиця вже реалізована, вона бачить той самий оновлений графік без другого джерела стану.
- [ ] Unit-тести перевіряють результати успіху та помилки; інтеграційний тест повторного запиту є запропонованим додатковим покриттям PRD.
- [ ] TypeScript і ESLint проходять.
