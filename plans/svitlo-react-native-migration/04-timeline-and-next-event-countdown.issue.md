# 04. Часова шкала та відлік до наступної події

Статус: виконано; реалізація та автоматизовані перевірки завершені. Платформне приймання — issue 10.
Джерело: [PRD](../svitlo-react-native-migration.prd.md).

Тип: HITL. User stories: 13–14, 16–18, 25, 27–28.

Погодження: користувач підтвердив щосекундне оновлення лише локального стану таймера та інтервалу, очищення таймера без наступної події й текст «до можливого відключення». Щосекундних запитів до сервера немає.

## What to build

На головному екрані вибраної локації показати поточні та майбутні інтервали, поточний стан, наступну відому подію й відлік до неї. Відтворити часову шкалу та картку Kotlin за кодом, зберігаючи всі типи станів.

Пояснити власнику продукту помилки оригіналу: ознака поточного інтервалу обчислюється лише при зміні графіка, а таймер може зберігати старе значення, якщо наступної події немає. Погодити виправлення і трактування переходу до можливого відключення, перш ніж завершувати цю поведінку. Рекомендація: відлік до найближчої відомої зміни стану із текстом, який не називає можливе відключення гарантованим.

## Acceptance criteria

- [x] Виправлення часової логіки та тексти переходів для можливого відключення погоджені й зафіксовані.
- [x] Часова шкала розрізняє чотири типи, не зливає можливе відключення або невідомий стан зі світлом.
- [x] Відображаються поточні та майбутні інтервали; поточний інтервал оновлюється з плином часу.
- [x] Таймер використовує поточний час і визначену наступну подію, не стає від’ємним і не зберігає попередню подію після зміни локації.
- [x] За відсутності наступної події або даних немає вигаданого відліку.
- [x] `24:00` є кінцем доби, без штучної втрати останньої хвилини.
- [x] Розрахунки ізольовані від React; unit-тести перевіряють межі інтервалів, півгодинні переходи, різні типи та відсутність події з контрольованим часом.
- [x] Компонування шкали й таймера відповідає Kotlin-коду; TypeScript і ESLint проходять.
