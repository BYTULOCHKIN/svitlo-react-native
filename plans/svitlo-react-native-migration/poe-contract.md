# Перевірений контракт Полтаваобленерго

10 жовтня 2026 року виконано POST до `https://www.poe.pl.ua/customs/newgpv-info.php` з form-urlencoded полем `seldate={"date_in":"10-10-2026"}` та заголовком `X-Requested-With: XMLHttpRequest`.

Отримано HTTP 200 та HTML: таблиця `turnoff-scheduleui-table`, tbody з дванадцятьма підчергами, назва черги з rowspan, 48 півгодинних клітинок на день. Класи `light_1`, `light_2`, `light_3` відповідають типам оригінального Kotlin-парсера. Кінець 48-ї клітинки — 24:00.

Відповідь збережено як JSON-фікстуру для повторюваних тестів без мережі. Фікстура не використовується як fallback у застосунку.

Порожній HTML або невідома структура не підтверджують відсутність відключень.

У межах issue 05 перевірено відповіді за 1 жовтня, 1 вересня та 1 серпня 2026 року. Вони мають HTTP 200 і контейнер `gpvinfodetail` без таблиці. Текст містить дату та повідомлення про те, що застосування графіка погодинного відключення у Полтавській області не прогнозується. Це підтвердження для області, а не окремої черги. Відповідь за 1 жовтня збережена окремою тестовою фікстурою. Парсер перевіряє повний зміст повідомлення та збіг дати; інші формулювання залишаються невідомим форматом.

За такого повідомлення збережена локація отримує обласне підтвердження. Для першого вибору перелік черг не вигадується: користувач бачить пояснення і може повторити завантаження. Повний графік 00:00–24:00 лише зі світлом також підтверджує відсутність запланованих відключень для відповідної черги.

Локальна ідентичність застосунку: `ua.svitlo.rn` із суфіксами середовищ. Expo/EAS account і project ID задаються лише через `EXPO_ACCOUNT_OWNER` та `EAS_PROJECT_ID`; значення Obytes прибрані. Це не налаштування публікації.
