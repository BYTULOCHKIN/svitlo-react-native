# 02. Реальний push і перевірка безкоштовної платформи

Тип: HITL.

Статус: Worker розгорнуто, remote API/D1 smoke PASS; власні EAS, Firebase Android і FCM v1 credentials налаштовано. APK встановлено на Samsung; реальний push, tap до картки, окремий cold launch і зміна OS permission перевірені. Cloudflare gate FAIL за доступом до джерела: повторні таймаути. Хмарний fan-out на 100 інсталяцій не виміряно. Задача не завершена; 03–15 не починаються.

Джерело: [PRD](../svitlo-notifications.prd.md). [Погоджене розбиття](../svitlo-notifications.issues-proposal.md).

User stories PRD: 2, 17, 18, 19, 20, 22, 26, 37, 38.

## What to build

Публікація з пілота надсилається через Expo на фізичний телефон із закритим застосунком і відкриває свою картку. Пояснення після першого вибору черги керує запитом дозволу. Прототип у Cloudflare вимірює реальний шлях отримання графіка, збереження події та розсилки для 100 тестових інсталяцій.

Участь людини: забезпечити власні Cloudflare/Expo та FCM/APNs доступи, за потреби платформні credentials, і звірити виміряний висновок про безкоштовний кандидат. Код, тести й відтворюваний сценарій готуються до перевірки.

## Acceptance criteria

- [x] Системний дозвіл запитується лише після «Увімкнути сповіщення». Відмова не блокує історію; фактичний стан ОС показано, є перехід до її налаштувань. Native-відмову перевірено через OS settings; натискання початкового OS deny не підтверджено.
- [x] Налаштовані власний Expo/EAS проєкт і відповідні credentials; доставку та відкриття запису підтверджено на Samsung. У звіті чітко відокремлено неперевірені платформи.
- [ ] Worker фактично отримує й валідно обробляє графік обленерго; перевірено cron, REST-доставку, початковий fan-out на 100 інсталяцій, CPU, підзапити та квоти D1.
- [ ] Є виміряний висновок щодо безкоштовного кандидата. Непроходження обмежень блокує наступні задачі до погодженого перегляду архітектури; платний тариф не вмикається автоматично.

## Implementation / validation

Підготовлено Expo Notifications permission flow, реєстрацію токена й стану ОС, атомарний outbox, пакетний Expo REST transport, перехід до картки, D1 adapter, міграцію та Worker з cron/private pilot trigger. [Відтворення й звіт](../../server/notifications/pilot.md).

Локальні тести перевіряють відсутність автоматичного запиту дозволу, відмову, OS settings, тимчасову відсутність токена, захист delivery API, fan-out на 100 одержувачів, повторні виклики, зміну токена та збереження історії після помилки доставки. Wrangler dry-run і локальні workerd/D1 HTTP smoke та cron пройшли; реальне джерело доступне з локального workerd.

11 жовтня 2026 року виправлено прив’язку D1, застосовано обидві віддалені міграції й розгорнуто Worker. https://svitlo-notifications-pilot.svitlonorify.workers.dev/health повертає 200 `{"ok":true}`; remote smoke перевірив реєстрацію, delivery API з відмовою дозволу, власну порожню історію, 401 із чужим секретом і 404 приватного маршруту без авторизації. `PILOT_RUN_TOKEN` збережено після деплою.

Після явного погодження користувача створено `svitlo-expo-fcm` у власному Firebase `svitlode-e9787ac8`, надано лише `roles/firebasecloudmessaging.admin`, збережено всі попередні IAM bindings та згенеровано один локальний ігнорований ключ. FCM v1 credentials призначено в EAS для `ua.svitlo.rn.development`; read-only перевірка підтвердила відповідність ключа та проєкту. Preview/production і APNs не налаштовано.

Samsung SM-S928U1 / Android 16: APK встановлено, empty-history Maestro PASS. Виправлено трактування першого Android permission стану; системний запит спостерігався після кнопки. Native-перевірки підтвердили історію при відмові через settings, очищення token у D1, повторну реєстрацію після ввімкнення, фактичний показ cron push, відповідну картку та cold launch окремого Expo test replay без нової події. Обидві Expo receipts `ok`. TypeScript і lint PASS; 31 Jest suites / 147 tests PASS. iOS, APNs, screen reader та foreground-показ не перевірені.

Cron фактично працює, але `sourceValid=false` повторюється з таймаутом близько 15.5 с; альтернативні URL з remote preview також дали таймаут. Локально живий поточний графік із 12 чергами отримано за 279 ms. Для перевірки доставки публікацію створено локальним приватним helper у real remote D1, після чого її outbox розіслав розгорнутий cron: один accepted push, CPU 7 ms, 5 SQL. Це не успішний доступ Worker до джерела й не вимірювання fan-out на 100. Критерії джерела та повного cloud budget залишаються відкритими; причина недоступності ще не встановлена. Деталі й точні межі доказів — у [звіті пілота](../../server/notifications/pilot.md).
