# Налаштування та попередження: задачі 05–08

Стан: код і автоматичні перевірки завершені; тестова D1 PASS. Production-розгортання та новий APK готуються. Фізичний Samsung не підключено на момент підготовки звіту.

## Поведінка

- Загальний перемикач керує тільки регіональними push про публікації та зміни. Історія цих подій зберігається незалежно від перемикача й дозволу ОС.
- Кожна локація має окреме попередження про запланований `off`, увімкнене за замовчуванням. Старі локації мігрують без втрати назв, іконок, черг та активного вибору. Перемикач є в налаштуваннях сповіщень і у формі локації.
- Налаштування зберігаються разом із монотонною ревізією в MMKV та передаються до захищеного `PUT /v1/preferences`. Сервер ігнорує старішу ревізію, повтор тієї самої є ідемпотентним, конфлікт вмісту тієї самої ревізії повертає 409. Вибір активної локації та зміна іконки не запускають зайву синхронізацію. Видалення останньої локації теж синхронізується.
- UI показує помилку/повтор синхронізації та не стверджує, що офлайн-зміни вже застосовано сервером. Повне відновлення офлайн-історії залишається задачею 11.
- Попередження формується у хвилину, що починається за 10 хвилин до `off`. Пропущена хвилина після простою не наздоганяється; пізно знайдене нове відключення не спричиняє запізнілого попередження. `possible`, `unknown` та відновлення світла не створюють попереджень.
- Допустимий кеш — не старіший за 5 хвилин від успішної перевірки. Невдалий запит не оновлює цей час. Перед доставкою повторно перевіряються версія графіка, свіжість, початок відключення й актуальні увімкнені локації. Expo expiration — за секунду до початку відключення.
- Одна інсталяція + одна черга + один початок відключення дають одну картку та один push. Різні черги не об’єднуються. У картці всі початкові назви без обрізання; push скорочує довгий перелік, залишаючись нижче 4096 байтів. Історія не змінює початкові назви після редагування чи видалення.
- Час обчислюється в Europe/Kyiv. Попередження для 00:00 формується попереднього дня. Безперервний `off` через північ не створює другого початку. Неіснуючий локальний час під час весняного переходу пропускається; повторений осінній час має одну подію для першого входження.

Планувальник зберігає завдання в D1. Подія, історія та outbox створюються атомарно; унікальні ключі захищають від конкурентних запусків. Доставка надає пріоритет попередженням і обробляє до 16 пакетів по 100 за цикл. Налаштування не відновлюють уже скасовані queued push. Невизначена зовнішня доставка не повторюється навмання; повне відновлення залишається задачею 14. Позначки скасування вже сформованої історії залишаються задачею 09.

## Докази перевірок

- 55 серверних тестів: попередні сценарії та 12 нових перевірок налаштувань, часу, групування, конкурентності й міграції. Міграція зберігає `push_eligible=0`, стару історію, ticket, preferences та AUTOINCREMENT після видалення старої події.
- 103 тести Svitlo, включно з формою, незалежними перемикачами, реальною синхронізацією через клієнт, збереженням після restart, міграцією та повними назвами в картці. Компоненти не обмежують масштаб шрифту/кількість рядків; фізичний тест вузького екрана, 200% і TalkBack ще не виконано.
- TypeScript, lint, Node build та design checks PASS. Для thumb нового toggle додано перевірки контрасту on/off.
- Реальна ізольована D1: дві інсталяції, 12 черг, два згруповані mock push, історія без дозволу ОС, відхилення старої ревізії та restart без дублювання. Синтетичні дані видалено; реальний Expo у цьому сценарії не викликався.
- Один звичайний цикл для двох дат і 12 черг: 20 D1 statements, 261 rows read, 5 rows written; проєкція тихого циклу — 375840 читань і 7200 записів/добу. Це не повний benchmark 100 користувачів із 30 днями історії. Для claim і перевірки доставки використовуються індекси та перевірки лише поточного outbox, без побудови переліку всієї історії.

## Розгортання

Зробити приватну SQL-резервну копію, атомарно застосувати `0008-notification-preferences.sql` і `0009-outage-warnings.sql` через офіційний D1 SQL import, звірити всі попередні події, історію, outbox, кількості та foreign keys, потім оновити Render. Тестова D1 мігрована цим механізмом. Нової HTTP-точки доступу до production D1 не додається.

Старий APK продовжує отримувати тільки регіональні події: підписки локацій надсилає новий клієнт. Для перемикачів і попереджень потрібно встановити оновлений APK з тим самим production signing key.
